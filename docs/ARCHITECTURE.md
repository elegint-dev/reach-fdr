# Architecture

The contracts between the three parts: the **data bundle** the build emits,
the **SPL generator** (the only module that emits SPL), and the **design
system**. Changes to a contract go here first.

Constraints that apply everywhere:

- **Zero runtime network.** No CDN, no web fonts, no fetch to anything but
  the app's own files.
- **Zero build step.** `python3 -m http.server` from the repo root, open
  `http://localhost:8000/`. Plain ES modules, no bundler, no framework.
- **Stdlib-only Python** for the build. `node --test` (built-in runner, no
  dependencies) for JavaScript tests.
- **No number is hard-coded in UI or README.** Counts come from
  `app/data/manifest.json`.

## 2. Data bundle (`app/data/`)

Emitted by `python3 tools/build_knowledge_base.py`.
Everything is plain JSON, `sort_keys=True`, so diffs are reviewable.

```json
  "built_at": "2026-09-16T00:00:00Z",
  "content_hash": "sha256 of the other bundle files, concatenated in name order",
  "ta_version": "3.2.0",
  "counts": {
    "fields": 1792, "raw_fdr": 0, "ta_derived": 0, "cim": 0, "legacy": 0,
    "events": 275, "events_cim_normalized": 56, "events_cim_gap": 219,
    "enriched": 785, "enrichment_batches": 16,
    "decode_tables": 169, "decode_values": 1370,
    "edges_confirmed": 0, "edges_asserted": 0, "suggested_joins": 0,
    "roles": { "<role>": n }, "role_basis": { "<basis>": n },
    "routes": { "direct_anchor": 0, "one_hop": 0, "host_only": 0,
```

The UI reads `schema_version` first and renders a visible message instead of
the app if it is not the expected version. Every count the UI
displays comes from `counts`. The README's stats block is regenerated from this
file between `<!-- reach:stats -->` markers by `--readme README.md`.

### 2.2 `fields.json` — `{ [name]: FieldRecord }`

One namespace: raw FDR, TA-derived and CIM names all live here. Raw FDR names
are CamelCase; TA/CIM names are snake_case; there are no collisions today and
the build **fails** if one appears.

```jsonc
{
  "name": "ResponsiblePid",
  "layer": "raw_fdr",              // raw_fdr | ta_derived | cim
  "legacy": false,                 // true for *_decimal twins
  "type": "keyword",               // from the field catalogue; "" if unknown
  "in_catalogue": true,
  "observed": true,                // appears on ≥1 event in the public corpus

  "role": "identifier",            // see roles below
  "role_basis": "enrichment",      // decode_table | meaning_sibling | dotted_prefix
                                   // | name_convention | enrichment | none
  "role_disagreement": null,       // or { "enrichment": "other" } when the
                                   // winning basis and enrichment differ

  "meaning": {                     // null when nothing on disk explains the field
    "description": "…",
    "hunting_notes": "…",
    "data_format": "…",
    "source": "enrichment",        // enrichment | decode_table | ta | reference
    "confidence": "high",          // enrichment only; null otherwise
    "evidence": "…"                // enrichment only; null otherwise
  },

  "events": ["ConfigurationProfileModified", "LoginItemAdded"],
  "event_count": 2,

  "cim_targets": [                 // raw → CIM/TA, event-conditional
    { "cim_field": "process_id", "via": "EVAL", "sourcetype": "crowdstrike:events:sensor",
      "events": ["ProcessRollup2", "…"], "statement": "case(event_simpleName IN (…), TargetProcessId, …)" }
  ],
  "sources": [                     // TA/CIM → raw (the walk-back). Empty on raw fields.
    { "raw_field": "TargetProcessId", "via": "EVAL", "sourcetype": "…",
      "events": ["…"], "statement": "…" }
  ],

  "decode": null,                  // or { "lookup": "crowdstrike_X.csv",
                                   //      "meaning_field": "X_meaning",
                                   //      "values": { "0": "…" } }   — full table
  "conversions": [ { "op": "epoch_ms_to_time", "note": "…", "spl": "…" } ],

  "edges": ["e_context_to_target"],          // ids into edges.json, src OR dst
  "suggested_joins": [                       // from enrichment; NEVER an edge
    { "to": "ImageFileName", "why": "…", "confidence": "medium" }
  ],
  "same_role_fields": ["ContextProcessId", "…"],   // informational only

  "route": {
    "summary": "one_hop",          // direct_anchor | one_hop | host_only | mixed
                                   // | unobserved | derived
    "explain": "…",                // one plain sentence, written by the build
    "by_event": {                  // every observed (field, event) pair
      "LoginItemAdded": { "route": "one_hop", "handles": ["ContextProcessId"], "is_anchor": false }
    },
    "derived_from": []             // for route=derived: the raw source field names
  },

  "audit": { "sample_events_seen": { "LoginItemAdded": 1 } }   // fixture provenance.
                                   // NEVER rendered as frequency.
}
```

**Layer rules.** `raw_fdr`: in the field catalogue or observed on an event and
not produced by the TA. `ta_derived`: produced by a `LOOKUP` (`*_meaning`,
`aid_*`, `appinfo_*`, `userinfo_*`, …). `cim`: named as the output of an `EVAL`
(CIM membership wins when both apply). The one `FIELDALIAS` is `cim` if its
target is a CIM field name, else `ta_derived`.

**Role precedence.** `decode_table` > `meaning_sibling` > `dotted_prefix` >
`name_convention` > `enrichment` > `none`. `classify()` learns snake_case CIM
names (`process_id`, `parent_process_id`, `dest`, `src`, `user`, `file_hash`,
`file_path`, `*_time`, `*_count`, `*_id`, …) so the TA/CIM layer classifies on
convention too. Whatever cannot be classified stays `unclassified` with
`role_basis: none`.

**Route rules** (per `(field, event)`): `direct_anchor` if the event is
`ProcessRollup2` or `SyntheticProcessRollup2`; `one_hop` if the event carries
any of `ContextProcessId`, `TargetProcessId`, `ParentProcessId` **and is on the
sensor sourcetype**; `host_only` otherwise. On `crowdstrike:events:external`
those names are not handles; the by-event entry carries `external: true`. Field summary: the single route if all events agree, else `mixed`;
`unobserved` when `events` is empty and layer is `raw_fdr`; `derived` when
layer is `ta_derived`/`cim` (`derived_from` names the raw sources; the UI shows
their routes).

**Roles.** The existing set plus enrichment's: `process_id thread_id tree_id
agent_id customer_id event_id hash user_id timestamp file_path command domain
ip port mac enum enum_label version count register size bool flag platform
event_name identifier container other unclassified`.

```jsonc
  "pid_spaces": { "TargetProcessId": true, "RawProcessId": false },  // carries both? (anchor for translation)

```

### 2.4 `edges.json` — `[ Edge ]`, from `data/curated/edges.json`, validated

```jsonc
{
  "id": "e_context_to_target",
  "src": "ContextProcessId", "dst": "TargetProcessId",
  "kind": "causal_attribution",      // process_lineage | causal_attribution | tree_grouping
                                     // | os_pid | host_enrichment | file_enrichment
                                     // | user_enrichment | detection_handle
  "basis": "asserted",               // confirmed_ta | asserted   (nothing else is an edge)
  "basis_ref": "DESIGN.md §join-graph; CrowdStrike data model",   // REQUIRED, non-empty
  "cardinality": "n:1",              // n:1 | 1:1 | n:n | unsafe
  "scope": ["aid"],                  // [] global | ["aid"] | ["aid","time"]
  "src_sourcetype": "crowdstrike:events:sensor",
  "dst_sourcetype": "crowdstrike:events:sensor",   // or the inventory sourcetype
  "target_label": "the process that caused this event",
  "note": "…",
  "hazard": null,                    // or { "level": "danger", "text": "…" }
  "mechanism": "query",              // query | search_time_lookup (curated)
  "lookup_keys": ["aid", "host_res_aid"],  // search_time_lookup only (curated): the
                                     // fdr_field(s) the TA's LOOKUP- rows are keyed on
  "automatic_on": ["crowdstrike:events:sensor"],  // DERIVED: sourcetypes the stanza fires on
  "yields": ["aid_computer_name", "…"]            // DERIVED: ta_derived fields it puts on the record
}
```

Build validation: every `src`/`dst` exists in `fields.json` (dotted `aidmaster.aid`
style targets resolve to the ancillary table), `basis_ref` non-empty, `basis`
in the two allowed values. The `same_role_candidates` buckets are **not**
edges; they populate `same_role_fields`.

The original seven edges: Edges to add: `SHA256String → SHA256HashData` (asserted;
basis_ref: TA appinfo LOOKUP on `crowdstrike:events:external` + enrichment),
`AgentIdString → aid` (asserted; basis_ref: FDR_REFERENCE §3). **Not** added:
`ProcessId → TargetProcessId`.

### 2.5 `translations.json`

`data/curated/translations.json` copied verbatim after validation: every event in
`anchor_events`, `needs_join`, `raw_only` exists in `events.json`; every field
named in `fields` exists. The `pivot_to_anchor` direction's SPL is replaced
with a stats-based form (no `join`) in the curated file.

### 2.6 `decodes.json` — `{ [field]: { lookup, meaning_field, values } }`

Full tables, for in-browser value → meaning.

## 3. SPL generator — `app/lib/spl.js`

The **only** module that produces SPL strings. Views never concatenate SPL.

```js
generate(pivot, params, opts) → { spl, hazards, asserted, missing, form }
```

**`pivot`** — one of:

| kind | meaning | required params |
|---|---|---|
| `edge` | follow an edge from `edges.json` (`pivot.edge` is the Edge) from a known value | `value`; plus whatever `edge.scope` names (`aid`, `earliest`+`latest`) |
| `trace` | observable → process (`cs_trace_process` shape) | `field`, `value`, `earliest`; `aid` optional (recommended) |
| `process_events` | everything a `TargetProcessId` did | `aid`, `tpid`, `earliest`, `latest` |
| `process_table` | every process on a host | `aid`, `earliest`, `latest` |
| `pid_lookup` | OS PID → `TargetProcessId` candidates | `aid`, `pid`, `earliest`, `latest` |
| `tpid_to_pid` | `TargetProcessId` → OS PID | `aid`, `tpid` |
| `host_lookup` | hostname → aid via aidmaster | `hostname` |
| `event_sample` | see this event's fields on real data | `event`, `earliest` |
| `decode` | decode a field via its TA lookup | `field` |

**`params`**: `{ index, sourcetype, aid, hostname, value, field, event, tpid, pid, earliest, latest }`.
Unbound params render as `$NAME$` placeholders and are listed in `missing`.
`index` defaults to `` `cs_index` `` (the macro); a note in `hazards` says so.
`sourcetype` defaults per pivot kind (`sensor` for telemetry; the inventory
sourcetype for enrichment edges; `external` for detection events) and is
always emitted explicitly.

**`opts`**: `{ form: "inline" | "macro" }`.

**Invariants — tested, not reviewed:**

1. A `RawProcessId` predicate is never emitted unless `aid` **and** both
   `earliest` and `latest` are bound. `pid_lookup` and any `edge` whose scope
   includes `time` **throw `SplError('unscoped_pid')`** otherwise — placeholders
   are not good enough for this one.
2. Any pivot that rests on an `asserted` relationship sets `asserted: true`
   and leads `hazards` with an `asserted`-level entry carrying the edge note.
3. Every emitted time bound is on `_time`, and `hazards` carries the note that
   `timestamp` and `ContextTimeStamp` are sensor-side and differ.
   **The SPL itself never contains a comment**; not every Splunk surface
   accepts them. Everything to be read alongside the search is in `hazards`,
   which the drawer renders above the code.
4. Only Splunk-Cloud-safe commands: `search eval stats eventstats where table
   sort convert rename fields head lookup`. Never `join`, `map`, `transaction`.
5. Values are quoted and escaped (`"` → `\"`, backslash → `\\`).
6. `hazards` is the list of `{ level, text }` the drawer renders at the point
   of result — every `edge.hazard`, the recycling hazard for `pid_lookup`, the
   hand-off caution for `tpid_to_pid`, the sourcetype-change note for
   detection handles.

Reference shapes are the five macros in `queries/macros/SPLUNK_CLOUD_MACROS.md`
and `data/curated/translations.json`; inline form expands them, macro form calls them.

## 4. Design system

### 4.1 Tokens (`app/styles/tokens.css`)

All on `:root`; dark is default; light under `prefers-color-scheme: light`
and `[data-theme=light]`.

```
--font-sans:  system-ui, -apple-system, "Segoe UI", Roboto, sans-serif
--font-mono:  ui-monospace, "SF Mono", Menlo, Consolas, monospace
--fs-1..-6:   12 13 14 16 20 24 px          --lh-body 1.45  --lh-tight 1.2
--sp-1..-7:   4 8 12 16 24 32 48 px
--radius-1 2px  --radius-2 4px
--bg-0 (page) --bg-1 (panel) --bg-2 (raised) --bg-3 (hover)
--fg-0 (primary) --fg-1 (secondary) --fg-2 (muted)  --line (hairline)
--accent (interaction: focus, selection — never data)
--trust-confirmed  --trust-asserted  --trust-suggested  --trust-inferred  --hazard
  each with -bg (tinted background) and -fg (text/border) variants
--layer-fg / --layer-bg   (monochrome; one pair for all three layers)
--focus-ring: 2px solid var(--accent), offset 2px
```

**Hue budget:** trust colours (teal / amber / violet / grey / red) and one
accent blue. Nothing else is coloured. Every `--trust-*-fg` on `--bg-1` and
every `--trust-*-fg` on its own `-bg` must pass 4.5:1 in both themes; the
gallery prints the ratios.

### 4.2 Components (`app/styles/components.css`, `app/components/*.js`)

Each is a function returning a DOM node. Class names are `r-<component>`
with `r-<component>--<variant>`.

| component | states / variants | notes |
|---|---|---|
| `omnibox` | idle, focused, results open, value-classified | `/` focuses; `Esc` clears; results are a listbox with roving focus |
| `chip` | `layer` (L1/L2/L3), `trust` (confirmed/asserted/suggested/inferred), `hazard`, `route` (here/one-hop/dead-end), `confidence` (meter inside a trust chip) | always has visible text; colour never alone |
| `ledger` | bands: here / automatic / one-join / suggested / unreachable | a real `<table>` per band with `<th>`s; rows focusable; `Enter` selects → drawer |
| `drawer` | empty, filled, copied, error (unscoped) | SPL block + param inputs + hazards + copy + inline/macro tabs |
| `callout` | why, expect, caution, hazard, note | icon + label + body |
| `step` | numbered workflow step with input, why, help | `required` marker |
| `keycap` | inline `<kbd>` | |
| `table` | dense data table | zebra, sticky header |
| `empty` | empty state | title, one line, first moves |
| `meaning` | description + trust line + evidence toggle | |
| `source-table` | CIM ↔ raw event-conditional mapping with statement | |

`app/gallery.html` renders every component in every state in both themes and
is the acceptance surface for the design system.

### 4.3 Keyboard map (`app/lib/keys.js`)

`/` focus omnibox · `Esc` back to omnibox · `↑ ↓` move within the focused
list/ledger · `Enter` select · `c` copy SPL · `e` cycle event scope · `1–4`
start cards · `[` `]` history back/forward · `?` key map · `t` toggle theme.
Keys never fire while an input is focused except `Esc`.

### 4.4 Route state

`#/f/<name>?on=<event>&sel=<row-id>` — `sel` is the selected ledger row so a
shared link opens with the drawer filled. Workflow params live in the query
string. State that is not in the URL does not exist.
